# DPAPP · 保存开发交接包(供 DeepSeek Harness 执行)

## Context

用户将把 DPAPP 项目目录作为工作区交给电脑上的 DeepSeek Harness(dsh)开发。本计划不再由我写代码,而是把本次会话敲定的全部产品/架构/里程碑决策落盘成三份文件,作为 dsh 的开发输入。其中 dsh 插件部分(远程开发桥)由 dsh 自行开发——它能直接读自己的源码验证插件 API,有问题当场修。

## 要保存的文件(3 个)

### 1. `docs/DESIGN.md` → v1.1(更新现有文件)

在现有 v1.0 基础上更新:
- **§3 功能规格**重写为四档:v1(F1–F10 + F11 消息编辑/重新生成/分支导航 + F12 基础操作包:置顶/重命名/临时对话/长按复制删除 + F13 dsh 远程开发·完整控制)/ v1.5(run_code 沙箱、记忆管理 UI、拍照提问)/ v2(网页端、全局搜索、原生工具桥+推送、RAG、连续语音)/ 暂不做(建议追问、提示词模板、自定义指令、系统分享、导出分享、生图)

### 2. `docs/HANDOFF-M0-M1.md`(新建,dsh 的第一份施工单)

M0+M1 的详细实施规格,即此前已拟定的实施计划全文:
- 第 0 步环境检查(node≥20/Flutter/Android SDK)
- 仓库结构(monorepo:server/ + app/)
- 消息分支设计:parent_id 消息树 + active_leaf_id、编辑重发=兄弟分支、重新生成=兄弟助手分支、GET 返回全树、PATCH 切活跃叶子、临时会话清扫
- M0 后端步骤 1–7(Fastify+better-sqlite3+zod;配对认证;会话 CRUD+PATCH;DeepSeek 适配层 client/events/mock,thinking=reasoning_content 增量;SSE 端点三态入参;stop;usage)
- M1 Flutter 步骤 1–6(riverpod/http/secure_storage/markdown;Pair/Conversations/Chat/Settings 四页;思考折叠、markdown 流式、长按菜单、编辑重发、重新生成、‹n/m› 分支切换器)

- 关键要点(SSE 内存累积一次性落库、协议单一来源、CORS 仅 dev 等)

### 3. `AGENTS.md`(新建,仓库根,面向编码 agent 的工作规范)

- 项目定位一句话 + 必读文档指引(先读 docs/DESIGN.md 再读 docs/HANDOFF-M0-M1.md)
- 技术栈约定(Node20+/TS/Fastify/better-sqlite3/zod;Flutter/riverpod)、代码风格(协议改动必须 server zod schema 与 app models 双侧同步)
- dsh 插件专项说明:这是给你自己运行时写的插件,遇到插件 API 与文档不符时,直接查本仓库/本机 dsh 安装的源码为准,修通后把实际可用接口记录进 docs/DESIGN.md §4.4
- 验证纪律:每完成一个步骤跑对应验证命令,MOCK=1 优先,真实 key 由用户提供
- 安全红线:DEEPSEEK_API_KEY 只存 server/.env(不入库);设备令牌 sha256 落库;不要在任何客户端代码写死密钥

## 交付物

DPAPP 目录内 3 份文件(docs/DESIGN.md v1.1、docs/HANDOFF-M0-M1.md、AGENTS.md),用户可直接将整个目录交给 dsh 开工。代码实施(M0 起的 server/ 与 app/)由 dsh 按施工单执行,不包含在本计划内。
