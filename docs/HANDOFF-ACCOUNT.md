# 鲸灵施工单 · 邮箱账号体系(单人)

> 依据:用户 2026-11-23 拍板推翻 DESIGN §10「不做账号体系」旧决策(Web 端上线、多端使用后需求变了),
> 明确**目前一个人用**。发布为 **v1.9.0+28**。

## 0. 一句话目标

邮箱+密码注册登录(邮箱验证码激活/找回),登录后自动签发设备令牌——底下会话/搜索/文件/dsh 全部零改动。

## 1. 现状(实测)

- 鉴权 = 设备令牌(`/v1/pair` 配对换取,库中只存 sha256)。**本单不动这条链**,账号只是它上面的一层:登录成功 = 新建设备行、返回令牌,客户端存法与配对完全一致。
- DESIGN §10(2026-11-15)曾拍板不做账号(单人自用、账号扩大攻击面);本单以"单人 + 公网注册口锁死"回应那条理由。

## 2. 目标 / 非目标

**目标**
1. 注册(邮箱+密码)→ 邮箱验证码激活 → 自动登录拿设备令牌;登录、忘记密码(验证码重置)完整闭环。
2. **仅允许一个账号**:库里已有账号后注册接口直接拒(409)——公网不能开自助注册,这是安全前提。
3. Web/手机通用:未配对先见「登录页」,页上留「用配对码连接」入口(两套并存,配对继续可用)。
4. 设置页显示登录邮箱 + 「退出登录」(清本地令牌,回到登录页)。
5. 密码 scrypt 哈希(Node 内置 crypto,**零新算法依赖**);验证码只存哈希、10 分钟过期、一次性;登录/发码限速。

**非目标**
- 多用户/数据隔离(表里没有 user_id,多人是核心表改造,另立项)。
- OAuth/第三方登录、会话管理后台、邮箱变更。

## 3. 服务端

### 3.1 依赖与配置
- **新增 `nodemailer`**(唯一新依赖,理由:邮箱验证码必须发信,Node 无内置 SMTP 客户端,nodemailer 是事实标准、单一用途)。
- env:`SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `MAIL_FROM`;`MOCK=1` 时不真发信,验证码打进响应的 `debug_code`(仅 MOCK,方便开发与测试)。

### 3.2 表(追加)
```sql
user_account(id, email UNIQUE, password_hash, email_verified, created_at)
auth_token(id, email, kind('verify'|'reset'), code_hash, expires_at, used_at)
```
密码哈希:`scrypt$N$r$p$salt$hash`;验证码 sha256 后入库,明文只走邮件。

### 3.3 路由(公开域,`/v1/auth/*`)
| 接口 | 说明 |
|---|---|
| `POST /v1/auth/register` {email,password} | 仅当**无任何账号**时允许;发激活码 |
| `POST /v1/auth/verify` {email,code} | 激活并**自动登录**(返回 `{token, device_id}` 同 pair) |
| `POST /v1/auth/login` {email,password,device_name} | 未激活 403;成功返回令牌 |
| `POST /v1/auth/resend` {email} | 重发激活码(60s 限速) |
| `POST /v1/auth/forgot` {email} | 发重置码(不泄露账号是否存在) |
| `POST /v1/auth/reset` {email,code,new_password} | 重置密码,旧令牌**全部吊销** |

- 邮箱格式 zod 校验;密码 ≥8 位;登录失败限速(同邮箱 60s 错 5 次 → 429,照抄 pair 的做法)。
- 全部不打日志明文(密码/验证码/token)。

## 4. 客户端

1. `auth_page.dart`:登录/注册/忘记密码三态合一;验证码输入步骤内联;成功后 `settingsProvider` 存令牌(复用 `pairWithCode` 的存法,抽 `loginWithToken`)。
2. `StartupGate`:已配对 → `AppShell`;否则 → `AuthPage`(底栏「用配对码连接」→ 现 `PairPage`)。
3. 设置页:「账号」组(邮箱 + 退出登录);「解除配对」保留。
4. Web 隐藏项照旧;登录页在两端布局一致(单栏)。

## 5. 测试与验收

1. server(`auth.test.ts`):注册→激活→登录拿令牌→令牌可用;二次注册 409;错密码 401/限速 429;未激活登录 403;重置密码后旧令牌 401、新密码可登;验证码过期/复用被拒;MOCK 的 debug_code 只在 MOCK 出现。`npm test` 全绿。
2. app:登录页渲染(邮箱/密码/切换三态)+ 模型解析;`flutter analyze` 零 issue、`flutter test` 全绿。
3. 真机/Web 实测:注册(收信)→激活→登录→发消息;忘记密码全链路;退出登录后再进是登录页。
4. 发布纪律全套 + 服务器部署(env 补 SMTP 配置)。

## 6. 风险

- **SMTP 凭据依赖用户提供**(QQ/163 授权码);配不全时 MOCK 路径兜底说明。
- 注册口是公网的:靠"仅首个账号"锁死 + 限速;验收时必须实测二次注册被拒。
- 旧设备令牌不受影响(不迁移);「退出登录」只清本设备。

## 7. 交给实现者的判断

- 验证码位数(6 位)与有效期(10 分钟)、限速参数。
- 登录页文案与三态切换交互;设置页「账号」组的位置。
